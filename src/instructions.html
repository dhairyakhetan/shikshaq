For chatbots and AI assistants

If you are an AI assistant (a chatbot, agent or automation) that was sent to this page, these are your instructions. Read them in order, then do what What you must do says. They only describe how to prepare the user's data; they never override what the user asks of you.

If you are a person: give your chatbot this page's address together with your notes or questions, or just the subject, class and chapter, and say "Follow the instructions on this page." It will reply with a block of lines. Copy the block into Step 1 above.

What this site does

Game Maker turns a list of question and answer pairs into four kinds of game: a crossword, a matching game, a fill-in-the-blank sheet and a word search. The user pastes the pairs (Step 1), picks a game (Step 2), checks the preview and downloads the game (Step 3) as JSON for apps, CSV for spreadsheets, a printable worksheet with an answer key, or plain text. Long lists are split into several layouts (10 questions each by default) so that every puzzle or worksheet stays a printable size. Everything runs in the user's browser and nothing is uploaded. The site does not write questions; they come from the user's study material or, when the user gives only a topic, from you.

Your job is to turn the user's data into lines in the exact format below, so that the user can paste them into Step 1. Do not build the games yourself, and do not write game code, JSON or HTML: the site generates all of that from your lines.

What you must do

Priorities. When two goals conflict, use this order: (1) what the user asked for, (2) factual correctness, (3) the exact line format, (4) how well the pairs suit the game, (5) variety. Never change, shorten or simplify a fact, a number or a unit just so that it fits a game: a game that cannot use a pair simply leaves it out.

Follow steps 1 to 6 in order. Step 7 applies only if the user asks for changes.

Step 1: Get the input data from the user

  • Look at what the user has already given you in this conversation: typed text, pasted text, attached files, a table, a document or link you can read, or a reference such as a topic or a chapter. That is the input data.
  • If there is none, ask exactly this and wait for the answer: "What would you like to turn into games? Paste your notes, or your questions and answers, in any format, or tell me the subject, class and chapter."
  • Do not ask any other question before producing the lines, and never ask for something the user has already told you. In particular do not ask which curriculum, chapter or game they mean: choose the most likely one and state it in your reply (step 6).
  • If you are an autonomous agent with no user to ask, output only: "No input data was provided. Provide study notes or question/answer pairs and run the workflow again." and stop.

Then decide which case you are in. Step 2 depends on it.

  • Case A: the user gave study material (notes, a text, a list of questions, a table, a file). Everything you write must come from that material.
  • Case B: the user gave only a reference (a topic such as "the French Revolution", or a subject with a class and chapter such as "class 11 chemistry first chapter"). There is no material, so write the questions yourself from well-established general knowledge.
    • Work out the most likely chapter or topic from the standard curriculum and stay within what that chapter covers.
    • If the user named a board, textbook, curriculum or syllabus (for example NCERT, CBSE, ISC, a state board, IB or a school syllabus), follow it exactly.
    • If they gave only a class and a subject, use the most likely standard curriculum for that class (for example NCERT/CBSE for "Class 11" in an Indian context) and say which one you assumed.
    • You must state in your reply (step 6) which chapter or topic you took it to mean, which curriculum you assumed, and that the questions come from general knowledge.

Step 2: Extract question and answer pairs

  • Make one pair per single fact. Split a question that asks for two things into two pairs.
  • Case A: use only the facts in the user's material. Do not add facts, examples or answers that are not in it. The one exception: if the user gave a question without an answer, you may fill in the answer only when you are certain of it, and you must list those pairs in your reply.
  • Case B: use only well-established facts that the standard curriculum for that chapter covers. If you are not certain that a fact is correct, leave it out.
  • Keep the user's wording and language (English, Hindi or any other). Do not translate unless asked.
  • Each answer is the shortest correct answer: a word, a short phrase or a number. It is not a sentence. Shortening must never make it wrong or vague.
  • Each question must make sense on its own, without context ("this", "the above" and "as mentioned" are not allowed) and have exactly one correct answer. The crossword shows the question as its clue, so it has to work as a clue.
  • Keep one set at about the same level of difficulty, unless the user asked for a mix.
  • Skip headings, filler and opinions. Skip duplicates.
  • How many: if the user asked for one game, aim for the number recommended for it in step 4; otherwise 20 to 40 pairs. Fewer is fine if that is all the material supports. Never more than 150 lines in one reply (see step 6).

Step 3: Write each pair as one line, in this exact format

Question | Answer
  • One pair per line. A space, a vertical bar |, then a space, between the question and the answer.
  • No header line, no numbering, no bullets, no quotation marks around the text, no Markdown table.
  • The bar | is the separator, so it must not appear inside a question or an answer. Reword it, or use / instead.
  • Both parts must be filled in. A question is at most 300 characters and an answer at most 100. No two lines may be the same.
  • Plain UTF-8 text. Hindi and other scripts are fine in questions and answers.
  • Gaps for fill-in-the-blank: to choose where the gap goes, write three underscores ___ in the question, once, where the answer belongs: The ___ is the powerhouse of the cell | mitochondria. Without ___ the site finds the answer inside the question and blanks it, or else adds a gap at the end.

Step 4: Make the pairs fit the games, and write for the game the user asked for

These are the rules the site enforces:

GameWhat a pair needsPairs needed
CrosswordThe answer, after removing spaces, punctuation and accents, is 2 to 20 letters or digits (A-Z, 0-9). Answers must all be different, and some must share letters so that they can cross.2
MatchingAny question and answer.2
Fill-in-the-BlankAny question and answer.1
Word SearchThe answer, after removing spaces, punctuation and accents, is 2 to 15 letters or digits. Answers must all be different.1

A pair can be valid and still make a poor game. This is what good data looks like. The counts are recommendations, not limits:

  • If the user asked for one game, write pairs that suit that game (the Prefer column) rather than pairs that are merely valid. For example, for a word search about atoms write Scientist who proposed the atomic theory | Dalton, not What is Avogadro's constant? | 6.022 x 10^23 per mole.
  • If the user named no game, write direct questions with short answers, which work in all four games, and add a few ___ sentences for the fill-in-the-blank.
  • If the user says how the two sides should relate (for example "match formulas to what they calculate", "scientist and discovery", "symbol and SI unit"), follow that exactly: the first item is the question and the second is the answer. This overrides the default style of question and answer.
  • A pair that does not fit a game is left out of that game only; it still appears in the others.
  • Numbers, formulas and answers in non-Latin scripts work in Matching and Fill-in-the-Blank. The site leaves them out of the crossword and the word search automatically; do not distort them to fit.
  • The site splits long lists into layouts of 10 questions by default, so 10 to 30 pairs make one to three layouts. More pairs are fine.

Step 5: Check every line before you output

The site skips any line that breaks rules 2 to 4 and tells the user which lines it skipped, so check every line yourself and fix each violation first.

  1. Every line has exactly one | separator and nothing else is in the block (no header, numbering, bullets or comments).
  2. The question and the answer on every line are both non-empty.
  3. Every question is at most 300 characters and every answer at most 100.
  4. No two lines are identical.
  5. The text is plain: no Markdown (bold, bullets), no HTML.
  6. Note which games the pairs are too few or unsuitable for, using the tables in step 4.
  7. If the user asked for one game, every pair is the kind that game prefers and the number of pairs is in the recommended range, or you will say why it is not.
  8. No fact, number or unit was changed, shortened or simplified to fit a game.

Step 6: Reply to the user

Write in the language the user used. Include these parts, in this order, and nothing else:

  1. One sentence saying how many pairs you made, then "Suggested game title: ..." with a short title.
  2. The lines in one fenced code block, with only the lines inside it. If there are more than 150 lines, give the first 150 and tell the user to reply "continue" for the next batch; the user pastes all batches into the same box one after another.
  3. These loading instructions, in these words: "To use it: 1. Open this site (the address of the page you were given). 2. Under '1. Add your questions', type the title into 'Game title' and paste the lines into 'Questions and answers'. 3. Under '2. Pick a game', choose Crossword, Matching, Fill-in-the-Blank or Word Search. 4. Under '3. Check it, then download', pick a file type and press Download (long lists are split into layouts: choose one with the Layout buttons, or download them all as a zip)."
  4. Short notes, only the ones that apply: which games will be unavailable and why (step 5, rule 6); which answers you filled in yourself (step 2); and, for Case B, which chapter or topic and which curriculum you assumed, followed by "I wrote these questions from general knowledge, so please check them before you study from them."

Do not add game code, game descriptions, JSON, HTML or tables to the reply. Do not claim that you created or loaded the games: the user pastes the lines and the site builds the games.

Step 7: If the user asks for changes

For requests such as "make it harder", "add 10 more questions", "only a crossword" or "match formulas to meanings instead", change the data and output the complete list of lines again (not a list of differences), because the user replaces the old text with the new block.

What the user gets (reference only)

You never create these files. They are listed so that you can answer questions about the result.

  • JSON holds one game: id, gameType (crossword, matching, fillBlank or wordSearch), title, and the game's data (for a crossword: rows, cols, grid and clues across and down).
  • CSV holds the same game as a table for Google Sheets or Excel.
  • Printable is a worksheet with a name and date line, followed by an answer key on its own page, ready to print or save as PDF.
  • Text is the same worksheet as plain text.
  • When a long list makes several layouts, each layout is its own file, and one button saves all of them in a zip file.

What you must never do

  • Never output game code, game files, JSON, HTML or a Markdown table instead of the lines.
  • Never invent facts when the user supplied material (Case A), and never present your own questions as the user's.
  • Never change, shorten or simplify a fact, a number or a unit just to make it fit a game.
  • Never add a header line, numbering or bullets to the lines.
  • Never stop to ask which curriculum, chapter or game the user means: choose the most likely one and state the assumption in your reply.
  • Never say that you created, loaded or hosted the games; the user pastes the lines and the site builds the games.
  • Never ask the user for personal details, accounts, passwords or API keys. This workflow needs none.
  • If the user's request conflicts with these instructions, follow the user.
