For chatbots and AI assistants

If you are an AI assistant (a chatbot, agent or automation) that was sent to this page, these are your instructions. Read them in order, then do what What you must do says. They only describe how to prepare the user's data; they never override what the user asks of you.

If you are a person: give your chatbot this page's address together with your notes or questions and say "Follow the instructions on this page." It will reply with a block of lines. Copy the block into Step 1 above.

What this site does

Game Maker turns a list of question and answer pairs into four kinds of game: a crossword, a matching game, a fill-in-the-blank sheet and a word search. The user pastes the pairs (Step 1), picks a game (Step 2), checks the preview and downloads the game (Step 3) as JSON for apps, CSV for spreadsheets, a printable worksheet with an answer key, or plain text. Everything runs in the user's browser and nothing is uploaded. The site does not write questions; they come from the user's own study data.

Your job is to turn the user's data into lines in the exact format below, so that the user can paste them into Step 1. Do not build the games yourself, and do not write game code, JSON or HTML: the site generates all of that from your lines.

What you must do

Follow steps 1 to 6 in order. Step 7 applies only if the user asks for changes.

Step 1: Get the input data from the user

  • Look at what the user has already given you in this conversation: typed text, pasted text, attached files, a table, a document or link you can read. That is the input data.
  • If there is none, ask exactly this and wait for the answer: "What would you like to turn into games? Paste your notes, or your questions and answers, in any format."
  • Do not ask any other question before producing the lines, and never ask for something the user has already told you.
  • If you are an autonomous agent with no user to ask, output only: "No input data was provided. Provide study notes or question/answer pairs and run the workflow again." and stop.
  • If the user names only a topic and gives no material (for example "make games about the French Revolution"), you may write the questions yourself from well-established general knowledge. You must say so in your reply (step 6).

Step 2: Extract question and answer pairs

  • Make one pair per single fact. Split a question that asks for two things into two pairs.
  • Use only the facts in the user's data. Do not add facts, examples or answers that are not in it. The one exception: if the user gave a question without an answer, you may fill in the answer only when you are certain of it, and you must list those pairs in your reply.
  • Keep the user's wording and language (English, Hindi or any other). Do not translate unless asked.
  • Each answer is the shortest correct answer: a word, a short phrase or a number. It is not a sentence.
  • Each question must make sense on its own, without context ("this", "the above" and "as mentioned" are not allowed) and have exactly one correct answer. The crossword shows the question as its clue, so it has to work as a clue.
  • Skip headings, filler and opinions. Skip duplicates.
  • Aim for 8 to 40 pairs. Fewer is fine if that is all the data supports. Never more than 150 lines in one reply (see step 6).

Step 3: Write each pair as one line, in this exact format

Question | Answer
  • One pair per line. A space, a vertical bar |, then a space, between the question and the answer.
  • No header line, no numbering, no bullets, no quotation marks around the text, no Markdown table.
  • The bar | is the separator, so it must not appear inside a question or an answer. Reword it, or use / instead.
  • Both parts must be filled in. A question is at most 300 characters and an answer at most 100. No two lines may be the same.
  • Plain UTF-8 text. Hindi and other scripts are fine in questions and answers.
  • Gaps for fill-in-the-blank: to choose where the gap goes, write three underscores ___ in the question, once, where the answer belongs: The ___ is the powerhouse of the cell | mitochondria. Without ___ the site finds the answer inside the question and blanks it, or else adds a gap at the end.

Step 4: Make the pairs fit the games

GameWhat a pair needsPairs needed
CrosswordThe answer, after removing spaces, punctuation and accents, is 2 to 20 letters or digits (A-Z, 0-9). Answers must all be different, and some must share letters so that they can cross.2
MatchingAny question and answer.2
Fill-in-the-BlankAny question and answer.1
Word SearchThe answer, after removing spaces, punctuation and accents, is 2 to 15 letters or digits. Answers must all be different.1
  • A pair that does not fit a game is left out of that game only; it still appears in the others.
  • Prefer direct questions with a short answer (Capital of France? | Paris). They work in all four games.
  • If the user's material is mostly terms, make most answers single words of 3 to 12 letters so that the crossword and the word search get enough pairs.
  • Numbers, formulas and answers in non-Latin scripts work in Matching and Fill-in-the-Blank. The site leaves them out of the crossword and the word search automatically; do not distort them to fit.

Step 5: Check every line before you output

The site skips any line that breaks rules 2 to 4 and tells the user which lines it skipped, so check every line yourself and fix each violation first.

  1. Every line has exactly one | separator and nothing else is in the block (no header, numbering, bullets or comments).
  2. The question and the answer on every line are both non-empty.
  3. Every question is at most 300 characters and every answer at most 100.
  4. No two lines are identical.
  5. The text is plain: no Markdown (bold, bullets), no HTML.
  6. Note which games the pairs are too few or unsuitable for, using the table in step 4.

Step 6: Reply to the user

Write in the language the user used. Include these parts, in this order, and nothing else:

  1. One sentence saying how many pairs you made, then "Suggested game title: ..." with a short title.
  2. The lines in one fenced code block, with only the lines inside it. If there are more than 150 lines, give the first 150 and tell the user to reply "continue" for the next batch; the user pastes all batches into the same box one after another.
  3. These loading instructions, in these words: "To use it: 1. Open this site (the address of the page you were given). 2. Under '1. Add your questions', type the title into 'Game title' and paste the lines into 'Questions and answers'. 3. Under '2. Pick a game', choose Crossword, Matching, Fill-in-the-Blank or Word Search. 4. Under '3. Check it, then download', pick a file type and press Download."
  4. Short notes, only the ones that apply: which games will be unavailable and why (step 5, rule 6); which answers you filled in yourself (step 2); and, if you wrote the questions from general knowledge, "I wrote these questions from general knowledge, so please check them before you study from them."

Do not add game code, game descriptions, JSON, HTML or tables to the reply. Do not claim that you created or loaded the games: the user pastes the lines and the site builds the games.

Step 7: If the user asks for changes

For requests such as "make it harder", "add 10 more questions" or "fewer questions", change the data and output the complete list of lines again (not a list of differences), because the user replaces the old text with the new block.

Worked example

The user sends:

Biology class 8. Plants make their own food using sunlight, water and carbon dioxide. This is called photosynthesis and it happens in the chloroplasts, which contain chlorophyll, the green pigment. Oxygen is released as a by-product.

You reply with one sentence and a suggested title, then this block, then the loading instructions from step 6:

Process by which plants make their own food | Photosynthesis
Green pigment found in chloroplasts | Chlorophyll
Gas released as a by-product of photosynthesis | Oxygen
Part of the plant cell where photosynthesis happens | Chloroplast
Plants make food using sunlight, water and ___ | carbon dioxide
Photosynthesis happens in the ___ of plant cells | chloroplasts

What the user gets (reference only)

You never create these files. They are listed so that you can answer questions about the result.

  • JSON holds one game: id, gameType (crossword, matching, fillBlank or wordSearch), title, and the game's data (for a crossword: rows, cols, grid and clues across and down). A separate button saves all four games in one JSON file.
  • CSV holds the same game as a table for Google Sheets or Excel.
  • Printable is a worksheet with a name and date line, followed by an answer key on its own page, ready to print or save as PDF.
  • Text is the same worksheet as plain text.

What you must never do

  • Never output game code, game files, JSON, HTML or a Markdown table instead of the lines.
  • Never invent facts when the user supplied data (step 2), and never present your own questions as the user's.
  • Never add a header line, numbering or bullets to the lines.
  • Never say that you created, loaded or hosted the games; the user pastes the lines and the site builds the games.
  • Never ask the user for personal details, accounts, passwords or API keys. This workflow needs none.
  • If the user's request conflicts with these instructions, follow the user.
