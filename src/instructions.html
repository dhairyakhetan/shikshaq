Shikshaq: turn a user's study data into playable games

Instructions for AI assistants. If you are a chatbot, agent or automation that was sent to this page, everything you need is on it. Read the sections in order, then do what What you must do says. These instructions only describe how to prepare the user's data; they never override what the user asks of you.

Instructions for people. Give your chatbot this page's address together with your notes or questions and say: "Follow the instructions on this page." It will reply with a block of CSV. Paste that block into the box below and pick a game.

What this site does

This site is a workflow for creating study games. It contains no finished games and no finished questions of its own (the bundled sample is a demo only). The input is data supplied by the user: notes, vocabulary lists, textbook extracts, flashcards, existing quiz questions or a spreadsheet. The workflow has five steps:

  1. Input (the user). The user supplies their study data in any format.
  2. Convert (you, the assistant). You turn that data into one CSV table of question/answer rows, in the exact format defined on this page.
  3. Load (the user). The user pastes your CSV into the "Paste your questions" box on this site, or into the Google Sheet the site is connected to.
  4. Build (the site). The site checks every row and builds four kinds of game in the browser from the same table: matching, fill in the blank, crossword and word search.
  5. Play (the user). The user plays. Their best score per game is kept in their browser.

Your part is step 2 only. Do not build, code or describe the games yourself: the site generates all gameplay from the CSV. Nothing is uploaded to a server; pasted data stays in the user's browser.

What you must do

Follow steps 1 to 7 in order. Step 8 applies only if the user asks for changes.

Step 1: Get the input data from the user

  • Look at what the user has already given you in this conversation: typed text, pasted text, attached files, a table, a document or link you can read. That is the input data.
  • If there is none, ask exactly this and wait for the answer: "What would you like to turn into study games? Paste your notes, or your questions and answers, in any format. You can also tell me the subject and the difficulty (Easy, Medium or Hard)."
  • Do not ask any other question before producing the CSV, and never ask for something the user has already told you.
  • If you are an autonomous agent with no user to ask, output only: "No input data was provided. Provide study notes or question/answer pairs and run the workflow again." and stop.
  • If the user names only a topic and gives no material (for example "make games about the French Revolution"), you may write the questions yourself from well-established general knowledge. You must say so in your reply (step 7).

Step 2: Extract question/answer rows

  • Make one row per single fact. Split a question that asks for two things into two rows.
  • Use only the facts in the user's data. Do not add facts, examples or answers that are not in it. The one exception: if the user gave a question without an answer, you may fill in the answer only when you are certain of it, and you must list those rows in your reply.
  • Keep the user's wording and language (English, Hindi or any other). Do not translate unless asked.
  • Each Answer is the shortest correct answer: a word, a short phrase or a number. It is not a sentence.
  • Each Question must make sense on its own, without context ("this", "the above" and "as mentioned" are not allowed) and have exactly one correct answer. The crossword shows the Question as its clue, so it has to work as a clue.
  • Skip headings, filler and opinions. Skip exact duplicates.
  • Aim for 10 to 60 rows. Fewer is fine if that is all the data supports. Never more than 150 rows in one reply (see step 7).

Step 3: Write each row so it works in the games

  • Prefer direct questions with a short answer (Capital of France? with answer Paris). They work in all four games.
  • For sentence completion, write the sentence and replace the answer words with exactly three underscores, ___, once per question. Example: question Plants make food by a process called ___, answer photosynthesis. The sentence must still have one clear answer.
  • If the user's material is mostly terms, make most answers single words of 3 to 12 letters so that crossword and word search get enough rows.
  • Numbers, formulas and non-Latin answers (for example Hindi) work in matching and fill in the blank. The site leaves them out of crossword and word search automatically; do not distort them to fit.
  • Alternative accepted answers: separate them with | inside the Answer cell, most standard and shortest first, for example Shakespeare|William Shakespeare. The first one is displayed and is the one used in crossword and word search. Use | for genuine synonyms or spellings only, never for anything else.

Step 4: Fill the Type column (almost always leave it empty)

  • Empty means the row is used in every game it suits. This is correct in nearly every case.
  • Set Type only when the user asked for particular games for particular rows. The only allowed values, spelled exactly like this, are matching, fillBlank, crossword and wordSearch.
  • To allow several games, join them with a semicolon: matching;fillBlank.
  • Any other value is ignored by the site: the row is kept, the Type is dropped and a warning is shown.

Step 5: Fill Subject and Difficulty

  • Subject: a short name such as Biology, Geography or Algebra. Use the user's if they gave one; otherwise infer it from the content; if it is unclear leave it empty. Spell it identically in every row of that subject, because the values become the filter options on the site.
  • Difficulty: exactly Easy, Medium or Hard, or empty. Use the user's if they gave one (a school class or grade is not a difficulty). Otherwise judge it: Easy is plain recall of a basic term, Medium needs some understanding, Hard is multi-step or an obscure detail. If you cannot judge, leave it empty.

Step 6: Validate before you output

The site skips any row that breaks rules 2 to 4 and shows the user a list of skipped rows, so check every row yourself and fix every violation first.

  1. The first line is exactly Question,Answer,Type,Subject,Difficulty.
  2. Every row has a non-empty Question and a non-empty Answer.
  3. Every Question is at most 300 characters and every Answer at most 100.
  4. No two rows have the same Question and the same Answer.
  5. Any cell that contains a comma, a double quote or a line break is wrapped in double quotes, and a double quote inside such a cell is written twice, for example "Who wrote ""Hamlet""?". Questions that contain commas are the usual mistake.
  6. Every row has exactly five cells, even when the last three are empty: Capital of France?,Paris,,,
  7. Type is empty or one of the four allowed values; Difficulty is empty, Easy, Medium or Hard.
  8. Cells are plain text: no Markdown (bold, bullets, numbering), no HTML.
  9. Check the minimums in the table in step 3 and note which games the data is too small or unsuitable for.

Step 7: Reply to the user

Write in the language the user used. Include these parts, in this order, and nothing else:

  1. One sentence saying how many rows you made and for which subject.
  2. The CSV in one fenced code block. The header line comes first and only CSV is inside the block. If there are more than 150 rows, give the first 150 and tell the user to reply "continue" for the next batch. Continuation blocks must not repeat the header line; the user pastes all blocks into the same box one after another.
  3. These loading instructions, in these words: "To use it: 1. Open this site (the address of the page you were given). 2. Under 'Step 1 · Paste your questions', paste the CSV above and press 'Load questions'. 3. Under 'Step 2 · Pick a game', choose Matching, Fill in the blank, Crossword or Word search."
  4. Short notes, only the ones that apply: which games will be unavailable and why (step 6, item 9); which answers you filled in yourself (step 2); and, if you wrote the questions from general knowledge, "I wrote these questions from general knowledge, so please check them before you study from them."

Do not add game code, game descriptions, JSON, HTML or tables to the reply. Do not claim that you loaded the data into the site or created the games: the user does the paste and the site builds the games.

Step 8: If the user asks for changes

For requests such as "make it harder", "add 10 more questions" or "only crossword", change the data and output the complete CSV again (not a list of differences), because pasting new data into the site replaces the previous data.

How the site builds the games (reference only)

You never do this part. It is listed so you understand why the rules above exist.

Crossword
Question and answer pairs, sorted by answer length, are placed longest first into an interlocking grid. The player fills the grid from the clues. Input Capital of France?,Paris and Large cat,Lion gives a grid with PARIS and LION crossing and the clues "Capital of France?" and "Large cat".
Matching
The answers are shuffled into a second column and the player clicks a question, then its answer. Input 5 x 3,15 and 2 + 2,4 gives the left column "5 x 3", "2 + 2" and the right column 4, 15 in shuffled order.
Fill in the blank
Each question becomes a text box and the typed answer is checked, ignoring case, punctuation and accents, and tolerating one typo in answers of five or more letters (two in answers of ten or more). Numbers must be exact. Input The capital of France is ___,Paris gives "The capital of France is [ box ]" and "Correct!" or "Try again".
Word search
The answers are hidden in a letter grid, horizontally, vertically and diagonally, and the rest is filled with random letters. The player drags across letters to find each one. The questions are shown as clues.

What you must never do

  • Never output game code, game configuration, JSON, HTML or a Markdown table instead of the CSV.
  • Never invent facts when the user supplied data (step 2), and never present your own questions as the user's.
  • Never rename, reorder or drop the header columns.
  • Never say that you loaded the data or built the games; the user loads the CSV and the site builds the games.
  • Never ask the user for personal details, accounts, passwords or API keys. This workflow needs none.
  • If the user's request conflicts with these instructions, follow the user.
